# IslandTime

A Minecraft Fabric mod for Hypixel SkyBlock that tracks island time, minion fuel/profit per fuel day, item stats, and more. Includes Discord alerts and a configuration GUI.

## Features

- **Island Time Tracking** — Tracks time spent on your private island with daily history
- **Fuel Day Tracker** — Tracks minion fuel and profit per real 24h fuel-day via a dedicated GUI (`/it fueldays` or `/it fueltime`). Placing a stack of fuel across a batch of minions (e.g. 4 each) creates that many entries immediately — one currently ticking down, the rest future/queued days already carrying their share of the auto-detected minion count and estimated fuel cost — bucketed by each physical minion's queued fuel-cycle number so refueling a full set in sequence still records one shared next cycle, rather than splitting counts just because the GUIs were opened at different times. Refueling while fuel is active continues directly into the next 24h period; after fuel runs out, a new refuel starts from its actual fueling time and does not reuse the old expiry. Fuel is counted from the **Time Remaining** line of the fuel in the minion's fuel slot (whole days, so each fuel added is one more day), not from the stack's count: Legendary fuel never stacks, Hypixel keeps its count at 1 and briefly shows a made-up count (3x) while a placement is answered, and it re-sends the slot with a new item uuid about once a second, none of which says how much fuel was added. Fuel-slot updates settle before counting a change, so server synchronization cannot split one insertion into multiple false fuel events — including the client's own prediction while a fuel is still being clicked into the slot (the slot isn't read while something is held on the cursor). Fuel placed just before you close the GUI (or click another minion) is still counted and reported on close, even though Hypixel never sends the updated Time Remaining if the GUI was closed within about a second of the click. Each fuel-day gets its own "fuel day up" Discord alert the moment IT runs out (not just once, when the entire queued batch finally finishes), so the next queued day is already ticking by by the time you're pinged about the one that just ended; the **Fuel Alert Only When All Fuel Expires** setting turns this around for setups that don't AFK, sending the alert once all of the fuel has run out, i.e. the last queued day is over and no minion's own fuel is still burning (fuel added in the meantime postpones it, and force-ending the cohort counts as the end). That only changes when the first alert goes out; whether it then repeats is up to **Repeat Fuel Alert Until**, so it still repeats by default. Each row/entry is titled with its day's actual start and end time (`DD/MM/YY HH:mm - DD/MM/YY HH:mm`), and a "Total Profit" widget in the top-right corner sums the final profit of every tracked day (supports up to the billions, e.g. `1.234B`). Each physical minion is identified by the permanent `uuid` of a minion upgrade in its upgrade slots (e.g. a Flycatcher) — upgrade items keep the same uuid forever, unlike the minion head, Enchanted Hoppers and other GUI items, which are regenerated with a fresh uuid (and a fresh `timestamp`, which is how they are filtered out) every time the menu is opened. Minions with no usable upgrade uuid fall back to the previous scheme — the armor stand's position and worn armor (not its entity UUID, which resets on server reload, and deliberately not whatever the stand is holding, since Hypixel gives each minion a randomly chosen sword every time it loads in, which silently changed the key on every rejoin) — and a minion already tracked that way is migrated onto its upgrade uuid, keeping all of its active and queued fuel-days, the first time its GUI is opened. Fuel-days saved under one of those older, sword-dependent keys are re-attached by block position (which holds exactly one minion) the first time the minion is opened, so nothing stranded by a sword re-roll is lost. Either way, fueling many minions in one sitting is tracked as that many distinct minions instead of collapsing into one. Supports placing full stacks of fuel at once (each unit queues an additional 24h fuel-day), auto-estimates each day's total fuel cost from a locked per-minion recipe price using Bazaar buy-order prices (the full Epic/medium Inferno Minion Fuel recipe cost: 100x Enchanted Coal + 6.25x Enchanted Sulphur (the 25 Sulphuric Coal, each crafted from 4 Enchanted Coal and 1/4 Enchanted Sulphur) + 3x Very Crude Gabagool + 6x the cheapest of all five distillates + 2x Inferno Fuel Block, with a manual total-cost override; the **Gabagool Distillate Only** setting prices only Crude Gabagool Distillate instead, for when you aren't AFKing and it is the only viable one). Use `/it fuelcost` or `/it fuelcost NUMBER` for a live full breakdown of all five distillate buy-order prices and the selected cheapest ingredient. The per-minion price is snapshotted once per fuel cohort/batch, existing automatic records retain their saved prices, and historical costs only change when you manually change the minion count or fuel cost; each day's total scales with its effective minion count (including manual count overrides), and re-fueling the same batch later never changes an already-recorded day's price — tracks mob-kill coins/day from a configurable 100%-AFK baseline scaled by that day's full-day AFK% (so coins accumulate steadily over the day, while the displayed AFK% itself is live — showing progress against time elapsed so far while a day is still in progress, rather than instantly looking tiny), and auto-tracks Crude Gabagool collected via Hypixel's in-game "[Sacks]" chat messages — including while a message-hiding mod like SkyHanni's "Sack Change Hider" is enabled, since the packet is read directly rather than from the visible chat log — (with a manual override, and a manually-entered sell price, for full profit-per-day tracking). The GUI's live values refresh once per second rather than every frame. Rows are color-graded red→yellow→green by AFK% (or, in estimated profit mode, by the estimated profit: red for a loss, yellow below 10m, green from 10m up), the day that is running right now has a white outline, and every field — including a manual minion-count override for when lag desyncs auto-detection — is directly editable, with minion-count, gabagool-amount, and fuel-cost override fields all accepting either an absolute value or a `+`/`-` prefixed delta (e.g. `+100000` or `-20000`) to adjust the auto-tracked value instead of replacing it. Start/end timestamps are editable in `dd/MM/yy HH:mm` format; changing an active or queued day moves later queued days with it. Future/queued days that haven't started yet show a condensed row (just minion count and fuel cost — everything else genuinely hasn't happened yet) and fill in normally once their cycle begins. **Enchanted Clock** (Time Warp) is accounted for: when Hypixel confirms "TIME WARP! You have successfully warped time for your Minions!" the current fuel day's end and every future fuel day (and each minion's own fuel expiry) move up by one hour, so the tracker, the alerts and the Discord pings follow the real fuel. If less than an hour of the current day is left, that day ends right away and the clipped time comes off the start of the next day instead, so the days that follow stay in step. Warps are remembered, so the estimate for fuel that ran out while the minion menu was closed accounts for them too
- The MoulConfig **Default Gabagool Price** persists across fuel days and is applied to every active and queued day (and any day that never received a price) that has not been manually overridden in the Fuel Day Tracker; days keep their price once they end. While a day still uses this auto price it shows a "temp auto price" comment, which disappears as soon as you change that day's price manually (clearing the price field reverts it to the default) or is replaced by any manual note. Editing a day only applies the fields you actually changed, and editing an active or queued day no longer suppresses its "fuel day up" alert. AFK percentages for an active manually corrected cycle use the elapsed time since its edited start (and may exceed 100% if the start is shifted forward); once the cycle ends, the complete edited duration is used. `/it fuelcost` fetches a fresh Bazaar snapshot, while automatic fuel records keep their locked price from the cohort start.
- **Item Stat Tracking** — Monitors a tracked item's `stats_book` value and alerts if it stops increasing or goes missing
- **Discord Webhook Alerts** — Sends notifications for island absence, tracked item issues, disconnects, composter running empty (or about to), an item evolving (see Evolution Alerts), when a minion's queued fuel-days run out (repeats until you empty your sacks, since sack storage caps mean AFKing further gains nothing; set the **Repeat Fuel Alert Until** dropdown to *Until Minion GUI Opened* or *Don't Repeat* if you aren't AFKing, as the gabagool then goes into your minions, and turn on **Fuel Alert Only When All Fuel Expires** to be told only when the whole stack of fuel has run out, rather than for each fuel-day. Both are in the Alert Speeds category and leave the alert as it was while untouched), and New Year's Celebration cakes (with a dedicated configurable webhook URL, configurable 5/15/30-minute reminders, and a final 5-minute warning)
- **Chat Relay** — Bridges island chat to/from Discord via a companion bot (outbound webhook + inbound localhost polling)
- **Backpack Preview** — Hover over a backpack to see its contents in an overlay; press Shift to inspect. It also works in the plain inventory screen (not only in a chest GUI), and closing a container while a preview is shown no longer leaves item tooltips hidden. Item counts of any size are shown, from -2,147,483,648 to 2,147,483,647 (including 0 and negative ones): counts of 1 to 99 are drawn as the game does, others abbreviated in the slot (`1.2k`, `12k`, `1.2M`, `2.1B`, `-1.2k`; 0 and negative ones in red) with the exact `Stack size` at the bottom of the tooltip in dark gray, with the components and other details (only for counts that aren't 1 to 99, as those are drawn exactly)
- **Favourite GUI** — Save and view container snapshots (e.g. minion layouts) as read-only overlays
- **Island Player Tracking** — Detects when visitors leave your island with optional chat/Discord notifications
- **Show Hidden Tooltips** — Reveals tooltips on items that have `hide_tooltip` set (e.g. GUI filler panes)
- **PPG Display** — Shows Price Per Gabagool in the Very Crude Gabagool sell offer menu
- **Ghost Command** — Client-side block removal with `/it ghost`
- **Composter Alerts** — Tracks your Garden composter the way SkyHanni does (stored organic matter, fuel and time left from the `Composter` tab widget — the right-click Composter menu is read as a second source for the stored amounts — plus your Composter Speed / Cost Reduction levels from the Composter Upgrades menu) to estimate when it runs empty, then sends a Discord alert when it does and, optionally, a warning a configurable number of minutes beforehand (Composter config category, 10 minutes by default, 0 to disable). Uses the main Discord webhook and ping ID. Enable the Composter tab widget (`/widget`) and open the Composter Upgrades menu once so the mod knows your upgrade levels; `/it composter` shows what it currently knows, and `/it composter debug` (or the Copy Debug Info button) copies the tab list and last Composter menu contents to your clipboard if the composter is not being found
- **Evolution Alerts** — Sends one Discord alert (main webhook and ping ID) for every `EVOLUTION! Your <item> has evolved!` chat message, e.g. when your Rosewater Flask evolves. One chat message produces exactly one alert, with no repeats. Toggle under Chat Alerts in the MoulConfig GUI
- **Keep Resource Pack** — Caches the Hypixel SkyBlock resource pack locally and keeps it active everywhere (even outside Hypixel), skipping re-download if unchanged. Whenever Hypixel offers a newer pack than the cached one, the new pack is downloaded and swapped in (replacing the old copy in your enabled packs, both for the running game and for the next launch) instead of silently staying on the old version
- **Component Display** — Shows specified item components (e.g. `id`, `color`) at the bottom of tooltips in dark gray
- **Player List** — Scrollable GUI (`/it players`) to manage a list of players with quick party/invite buttons, editable notes, and head skin display. Also mirrors recent chat to the left of the list; shift + right-click a mirrored line — or hover it and press the configurable **Copy Chat Message Key** (default `C`, toggle and key under Player List in the MoulConfig GUI; ignored while typing in the search box) — to copy its full raw component structure (text and hover text, including every sibling) to the clipboard, with a brief "Copied" confirmation — a diagnostic aid for reporting chat-parsing bugs and for capturing the exact text of a message you want an alert for
- **Sign Helpers** — Adds paste buttons to the sign edit screen with configurable pre-set text per line
- **WAILA (What Am I Looking At)** — Inspect any targeted block or entity with `/it waila`. Blocks show block ID, position, state properties, tile entity data, skull textures, and SkyBlock custom IDs. Entities show their full info: entity type, name, entity ID, UUID, position, size, flags, tags, riding relationships, health, equipment and held/framed items (with SkyBlock IDs and head texture hashes), and full NBT. Entities that vanilla's crosshair can't target — marker armor stands, dropped items, display entities and the like — are found by looking at them too and are labelled "untargetable"; a targetable entity under the crosshair always takes priority. Blocks and entities beyond normal reach work too: WAILA casts a ray from where you are aiming (up to a configurable range, 128 blocks by default) and inspects the first thing it hits, so blocks hide entities behind them. Bind a key in the **WAILA** settings category to run it without typing the command (unbound by default) Both come with `[+ Add ... to Highlighter]` buttons — for entities, one adds the entity ID and another adds the entity name
- **Highlights** — Multi-entry block and entity highlight system with a dedicated GUI (`/it highlights`). Each entry has its own target (block ID, `entity:` plus any registered entity ID such as `entity:item_frame`, `entity:glow_item_frame`, or `entity:armor_stand`, optionally with a case-insensitive name filter (matching the whole name) such as `entity:armor_stand[name=Sparkling Critter]` (or `entity:*[name=Sparkling Critter]` to match any entity type by name), `sb:` SkyBlock ID, or `skull:` texture hash), color, range, intensity, through-walls toggle, and optional area filter. Two per-entry toggles (defaults in the Block Highlight settings): **Partial** matches IDs and names by "contains" instead of exactly — `d` highlights every block with a `d` in its ID, `entity:ca` every entity type with `ca` in its ID (cat, cave_spider, ...), and name filters only need to contain the text (also works for `sb:` IDs and `skull:` hashes; air is never matched, and a scan keeps at most 20,000 block boxes); **Min Box** gives entities that have no hitbox — marker armor stands, markers, display entities and other 0-size things, as flagged by WAILA — a 1 block highlight box so they can actually be seen. Quickly add highlights from WAILA results or via `/it highlight add` (WAILA's entity buttons turn Min Box on for hitbox-less entities). Entity highlights follow moving entities smoothly (interpolated every frame, matching how the entity itself is drawn), drop off as soon as an entity is removed, and pick up new or renamed entities on the next game tick; **Smooth Entity Highlights** in the Block Highlight settings can switch the interpolation off if it ever misbehaves
- **Critter Safari Tracker** — On-screen widget listing the Critter Safari critters you have **not** caught yet this run (grouped by Forest/Cavern/Icy/Haunted biome) under a centered `caught/total` counter, so the list shrinks as you work through all 37 and you can see at a glance what is left. Catches are read from the `CAPTURE!` and `LOOT SHARE!` chat messages (including `SPARKLING` catches and the Hideyho "You found" variant); a caught critter flashes green and fades off the list over a second, and a critter that breaks out (`The Gimmiegold escaped your Critter Capsule!`) is shown in red until you land it. Optional announcements report each biome as you clear it (`Forest done (1m 12.7s)`, and `All done (1m 12.7s)` for the one that finishes the run) to party chat via `/pchat`, or only to your own chat as a local `[IslandTime]` message when that is turned off; timers start when the Safari ticket is handed in. The "Forest Minus Macaw" option reports `Forest done minus Macaw` / `All done minus Macaw` while Macaw is missing, then sends corrected `Forest done` / `All done` messages if Macaw is caught later. Saying `!missing` in public or party chat while inside the Safari replies in party chat with the uncaught creatures grouped as `Forest(Foxtrot, Macaw), Cavern(...)`; the response is capped at 200 characters and ends with `(and more...)` when needed. The tracker resets when the Safari Manager starts a new run — both the party line (`[NPC] Safari Manager: Looks good to me. Have fun out there!`) and the solo line (`[NPC] Safari Manager: I already saw your ticket, so you're free to go.`). Only rendered while you are inside the Safari, using the same tab-list area detection as Block Highlight (matched by keyword, so the shortened `Safari` area name and the biome sub-areas all count; this gate can be turned off if detection ever fails). The move screen also shows the area name currently detected, so mismatches are easy to spot. Toggle it, drag it anywhere on screen and scroll to resize it from the Critter Safari config category or `/it critters`. Also includes a **Sparkling Alert**: when a `SPARKLING` critter (the variant that awards a bonus Rainbow Feather) spawns near you, an XP pling plays once and a through-walls tracer line plus a large floating `SPARKLING` label mark it out. The alert, its sound, the tracer, the tracer color and the name tag are configurable under the Critter Safari category
- **Greenhouse Blueprint** — A Litematica-style ghost preview for Garden greenhouses, copied in game from a greenhouse you have built. Stand in the greenhouse plot and run `/it blueprint copy` for a preview of the area that would be saved: a gold frame around the 10x10 soil area and a colour-coded box (with the crop's name when you are close) for every crop the mod finds in it, updating live as you build. A copy records three things: the **blocks** in the crop layer, the **armor stands** (many custom crops are an armor stand on top of a plain crop's block, so a real nether wart and a nether wart with a stand on it are told apart), with everything they wear and hold, how they face and how they are posed, skull textures included, and the **soil floor** under every cell, so you can see which dirt types are needed to rebuild it. When it looks right, `/it blueprint save <name>` keeps it, and `/it blueprint addboard` adds it to the selected blueprint instead as the board for another plot (up to three boards, one per greenhouse plot; each plot shows the board you last saved for it, or `/it blueprint board <n>` picks one); `/it blueprint cancel` stops the preview. Once a blueprint is selected, standing in a greenhouse plot in the Garden draws everything that is still to be built over its cell as a **see-through copy of the real block** (the crop's model, and the right soil block wherever the floor is missing or wrong); armor stands are drawn as **see-through copies of the real stand**, wearing and holding what the copied one did (armor, items, custom skull textures), drawn by the game's own entity renderer. Whatever is already right disappears. A **red outline** is drawn around every block (air included), soil block and armor stand (with its armor) that the layout wants and that isn't right, and around anything in the area that the layout doesn't have; it also shows over a ghost, so a wrong block in a ghost's space is still flagged (**Outline Incorrect**, with **Outline Thickness** and **Outline Opacity** to tune it). Crops are matched by their exact block, so a red mushroom in a brown mushroom's slot counts as wrong. Crops that swap their block as they grow, rather than only going through the vanilla growth stages, are matched by the armor stand with the crop's head: a Wild Rose that is still wheat seeds, or a Moonflower, Sunflower, Cactus, Cocoa Beans, Melon, Pumpkin or mushroom that has yet to become its grown block, counts as right as long as its stand is the crop's, and a layout copied from one is saved with the grown block. **Crops Only On Correct Floor** (needs **Check Floor**) holds a crop's ghost, outline and name back until the soil under it is right (all of it, for a big crop), so you can build the floor first and the crops after; the legend says how many are being held back. A legend shows how many of each crop and soil block are right, and can hide itself while the greenhouse matches the layout perfectly (**Hide Legend When Complete**). Copies keep the world's own orientation, so they line up without turning; `/it blueprint rotate`, `mirror` and `align` (which fits the layout to what you have already built) are there for a greenhouse that is built the other way round. Only active in the Garden, using the same tab-list area detection as Block Highlight, and only over plots that have a greenhouse (recognised by the Carpenter NPC; **Show In Any Plot** skips that check, and `/it blueprint status` shows what the mod sees). Blueprints are stored in `config/IslandTime/greenhouse_blueprints.json`. Ghost block models and ghost armor stands (or plain boxes), the red outline's thickness and opacity, **Highlight Crop In Reach** (outlines the crop head you aim at while it is in hit range, since a head has no block border to show it can be broken), floor checking, crops-only-on-correct-floor, opacity, through-walls drawing, crop names, completed-crop hiding and the legend are configurable under the Greenhouse Blueprint category. `/it blueprint gui` (or the **Open Blueprint List** button in the Greenhouse Blueprint category) opens a blueprint list styled like the player list and fuel day screens: one row per layout with its boards, crops and source, a **Use** button to select it, a **Copy Code** button that puts a shareable import code for the layout on your clipboard, and a delete button (click twice). The **Import From Clipboard** button at the top reads such a code (`/it blueprint import` does the same from chat, and `/it blueprint export [name]` copies a code) and adds the layout as a new, selected blueprint named after the original (numbered if the name is taken). A code is a single short line of text (a few hundred characters for a big three board layout, mostly made of common CJK characters so it packs 14 bits to a character, rather than the thousands an item-by-item copy would take), so it can be pasted into Discord or anywhere else; it ends in a checksum, so one that was cut short or changed is refused instead of misread. It holds the layout only, never anything private: for each armor stand's items it keeps what is needed to draw a ghost (the item, a head's skin and a leather piece's colour, plus the name the checks compare by), not lore, enchantments or other item data. Imports are checked for size and sanity first, and the long `ITGH1:` codes of earlier versions can still be imported
- **Copy Skin** — Copy the skin texture of a targeted player head block to clipboard with `/it copyskin`, or copy from a skull item in any inventory/GUI by pressing a configurable keybind (default: `V`). Preserves transparency. The keybind and toggle are configurable in the MoulConfig GUI under Misc
- **Accounts** — `/it account` (or the Accounts config category) logs a Microsoft account in through Microsoft's code page, so the mod never sees a password. The login is swapped into the running game, so an expired or soon-to-expire login (they last 24 hours) is renewed **without disconnecting** from the server you are on; a server only checks it when you join. Accounts logged in this way are saved so you can switch between them from the screen (a switch applies to the next server you join), and a saved account's login is renewed in the background shortly before it expires (**Renew Login Automatically**). Only the Microsoft refresh token is kept, never a password, in `config/IslandTime/accounts.dat`, encrypted with Windows DPAPI (tied to your Windows user) or, on other systems, AES-256-GCM with a key in `accounts.key` that only your user can read. It stays on your computer and is never part of exported settings or logs; do not share the `config/IslandTime` folder with it in. Logging in needs a **Microsoft Client ID** (Accounts > Microsoft Client ID): an Azure app registration for personal Microsoft accounts with public client flows enabled, which Microsoft must approve for Minecraft (aka.ms/AppRegInfo). Mods that read the login once at startup keep their old copy
- **Skin & Capes** — `/it skin` (or the Accounts config category) changes the skin and cape on the account in use: **Paste Skin** reads a 64x64 or 64x32 image (or copied .png file) from the clipboard, **Set Skin...** takes a PNG path or a texture hash, **Model** picks classic or slim, and capes owned by the account can be worn or hidden. **Saved skins** sit below the capes: **Save** keeps the skin the account has now (its image, model and the cape worn with it) under a name, **Set Skin...** can save what it applies, and each saved skin has **Use** (applies the skin and puts its cape back on if the account owns it), **Rename** and a delete button (click twice). They are stored in `config/IslandTime/saved_skins.json` and `config/IslandTime/skins/`. `/it skin paste`, `/it skin hash <hash>` and `/it skin reset` do the same from chat, WAILA's skull output has a **[Use As My Skin]** button, and **Set Skin Keybind** (unbound by default) makes the head you hover in an inventory your skin. The change is made to your Mojang account straight away, but servers read your skin when you join, so others see it after you reconnect. Only needs the login the game is already using
- **Profit Calculators config category** — The settings and a run button for each profit command (`/it agingItems`, `/it cookieProfit`, `/it huntrapProfit`, `/it infernoProfits`) are together in one **Profit Calculators** category, with the four run buttons at the top and an accordion of settings for each below (they used to be under Misc and, for the Inferno estimate, Fuel Cycles). Existing values are carried over the first time the config is loaded.
- **Aging Items** — Compare profit per hour for all levelling items (Bottle of Jyrre, Dark Cacao Truffle, Discrite, Moby-Duck, Not Very Moldy Bread, Rosewater Flask) using live Bazaar prices. Configure time-bag and inventory slot counts for estimated hourly income (under Profit Calculators > Aging Items, which also has a **Compare Now** button). Add or remove custom item pairs with `/it agingItems add/remove`
- **Cookie Profit** — Compare profit per bit from spending Booster Cookie bits on Kismet Feathers, Magma Buckets, and Plasma Buckets using live Bazaar prices. Accounts for material costs (enchanted lava buckets) on crafted items. Configure your bits-per-cookie in the MoulConfig GUI under Profit Calculators > Cookie Profit
- **Huntrap Profit** — `/it huntrapProfit` ranks Huntrap placement locations by estimated shard profit per hour for five traps, using live Bazaar prices. Configure the Huntrap type, Hunter Fortune, Desert Temple buff, Forest/Combat Trap attribute levels and how many locations to show under Profit Calculators > Huntrap Profit. Profit is estimated from the average catch time (the 16-24h range averages 20h, reduced by the Huntrap tier and sped up by the buffs), locations that can catch several shards split their catches by weight or evenly when no weight is known, and hovering a shard shows every factor of its calculation. The data can be edited in game with **Edit Huntrap Data** (Profit Calculators > Huntrap Profit) or `/it huntrapEditor`, a list screen styled like the player list: each location has Disable/Enable, Edit and delete buttons, **+ Add Location** takes a name and a placement, **Shards** opens the catalog of shards (Bazaar id, rarity and category; each has Disable/Enable too, and deleting one removes it from every location that catches it), and inside a location **Rename / Move** changes its name and placement, **+ Add Shard** picks a shard (with a search box) and its weight, **Disable/Enable** turns that shard off at this location, **Weight** changes one (leave it blank for unknown) and X removes the shard. Disabling keeps the data but leaves it out of `/it huntrapProfit` as if it wasn't there: a disabled location isn't ranked, and a disabled shard (at one location or everywhere) is dropped from the odds, so the remaining shards' chances are worked out out of their own total; a location with every shard disabled is skipped. Disabled rows are greyed out and say so. Deleting needs a second click, and **Reset To Defaults** brings back the built-in data (everything enabled). Edits are saved in `config/IslandTime/huntrap_locations.json`; once that file exists it replaces the built-in data entirely, so shards or locations added in later mod updates only appear after a reset.
- **MoulConfig GUI** — All settings accessible from a single GUI opened with `/it` (alias: `/islandtime`)

## Installation

1. Requires **Minecraft 26.1** with **Fabric Loader** and **Fabric API**
2. Download the latest release from the [Releases](../../releases) page
3. Place the JAR in your `.minecraft/mods` folder

## Commands

All commands can also be configured from the GUI (`/islandtime`).

| Command | Description |
|---------|-------------|
| `/it` | Open the config GUI |
| `/it recent` | Show last 7 days of island time |
| `/it trackedIslandTime <date>` | Show a specific date (DD-MM-YY) |
| `/it fueltime` | Open the fuel day tracker GUI (per-fuel-day fuel/profit stats). Same as `/it fueldays` |
| `/it fueltime <YYYY-MM-DD>` | Show a quick chat summary for a specific day |
| `/it fuelcost [NUMBER]` | Show the Bazaar buy-order cost breakdown for one fuel or NUMBER fuels, including all five distillate prices and the cheapest selection (or Crude Gabagool Distillate when **Gabagool Distillate Only** is on) |
| `/it infernoProfits [MINIONS]` | Show what the minions of your current fuel cohort (or MINIONS minions) earn in a whole fuel day on Rare (Fuel Gabagool), Epic (Heavy Gabagool) and Legendary (Hypergolic Gabagool) fuel, using the minion tier, speed bonuses, Super Compactor, eyedrops and price settings of the Profit Calculators > Inferno Profits options (never AFK mode). Hover a fuel for the full breakdown |
| `/it fueltime debug` | Inject a fake day record and attempt a save (diagnostics) |
| `/it minionid` | With a minion's GUI open, show how that minion is being identified and what each upgrade slot contains, including why an upgrade's uuid was rejected (diagnostics) |
| `/it guilog [start\|stop\|status\|note <text>]` | Record a diagnostic log of container GUI activity to `config/IslandTime/gui-debug/` while it runs (see [GUI debug log](#gui-debug-log)) |
| `/it composter` | Show composter tracking status: last reading (tab widget or Composter menu), known upgrade levels, estimated time until empty and which resource runs out first |
| `/it composter debug` | Copy the tab list lines and the last Composter menu contents to the clipboard, for troubleshooting when the composter is not found |

## GUI debug log

`/it guilog start` starts writing a log of everything that happens in container GUIs (minion menus, the Bazaar, chests...) to `config/IslandTime/gui-debug/gui-debug-<date>-<time>.log`; `/it guilog stop` ends it (so does disconnecting, or the file reaching 64 MB). It is off by default and costs nothing while off. It exists to pin down fuel counting bugs (a fuel counted twice, or not at all) by showing, in order, what you did, what the game predicted and what the server answered. Use `/it guilog note <text>` to mark a moment ("closed this one instantly") so it can be found in the file, and `/it guilog status` to see whether it is running.

Every line is `time +msSinceStart tTickNumber TYPE details`, flushed straight to the file:

- `OPEN`, `OPEN_SLOT`, `SLOT`, `CURSOR`, `STATE`, `CLOSE`: the menu as it opens (every non-empty slot), every change to a slot or to the item on the mouse between ticks (old → new), changes of the menu's state id, and the moment it closes (a change made in the same tick as the close is included).
- `CLICK_RAW`, `KEY`: mouse presses and key presses in the GUI, with the hovered slot and item, before the game acts on them.
- `CLICK_SENT`, `CLICK_PREDICTED`: the click the game sends to the server, then what the client predicted it would do before the server answered.
- `PACKET_IN`, `PACKET_DONE`: each container packet from the server (slot, whole-menu contents, cursor item, close, open) with all its fields, just before and just after the client applies it. Each shows the client's state, which is how an answer that arrives after the GUI was closed shows up.
- `MINION_CLICK`: an armor stand being right-clicked, which is how a minion GUI is attributed to a physical minion.
- `TRACKER`: every decision the minion fuel tracker makes: which minion it is tracking, when the baseline is locked, when it is waiting for the cursor to clear or the slot to settle, what it compared (the fuel's Time Remaining in days, or its stack count when it has none), a placement it saw in flight, what it counted, the chat message it sent, and why nothing was counted when the GUI closed.

Items are written as `count "name" fp=<fingerprint> sbId=<SkyBlock id> uuid=<item uuid>`. The first time a fingerprint appears, an `ITEMDEF` line just before it holds that item's full data: name, lore and every item component as SNBT. The fingerprint covers the count, so two lines with the same `fp` are the same item, uuid included, and the same item at another count has another `fp`. The end of the file counts the lines of each type, which shows which hooks never fired.

Chat is not recorded, and the log holds no account name, but item data can include whatever the item carries (a Hypixel item uuid, or a player name on some items), so look through it before sharing it. To share it, copy the file into the repository (e.g. a `debug-logs` folder) and push it.

## Configuration

Settings are saved in the `config` folder as `islandtime*.txt` files (and `fuel_days.json` for the fuel day tracker). Never share these publicly — they contain your Discord webhook URL.

Minion identities (which permanent upgrade uuid belongs to which tracked minion) are kept in `config/IslandTime/minion_identities.json`. It is written automatically the first time each minion's GUI is opened and is shared by all fuel data sets; deleting it only costs the mod its memory of past minion identities, which it rebuilds as each minion is opened again. The file holds one record per minion — its canonical id, the minion's name, its position, and the upgrade uuids that resolve to it — with the armor-stand equipment string shared in an `armorTypes` table at the top rather than repeated in full on every entry. Files written by earlier versions used a flat alias list instead; those are detected and converted automatically on the next launch, with nothing lost.

The Fuel Day Tracker keeps its history in **data sets**, each in its own file in `config/IslandTime`. There are always two built-in ones, **Main** (`fuel_days.json`, your real data) and **Debug** (`fuel_days_test.json`, what the old "Use Test Data File" toggle switched to), plus any you create, stored as `fuel_days_set_<id>.json`. The **Open Data Sets** button in the Fuel Cycles config category, the **Data Sets** button in the Fuel Day Tracker and `/it datasets` open the list, where **+ New Data Set** creates an empty one (optionally using it right away), **View** browses a set in the Fuel Day Tracker (read-only, and it doesn't change what is being used), **Rename** gives a set another name (the built-in ones too; only the name changes, not its file), **Use** makes it the set that new fuel is recorded into, and a custom set that isn't in use can be deleted (click the X twice). The set in use is saved in `config/IslandTime/fuel_datasets.json` and is the one shown the next time you start the game. A set that is only being viewed shows a banner saying so, with a **Use This Data Set** button at the top, so you can browse the others without changing what is in use. Switching saves the current set first and keeps its own backups, and an older install that had the test file switched on starts on the Debug set. Going back and forth between a set's day view (**View**) and the Data Sets list replaces the open screen rather than stacking them, so Esc always closes straight back to wherever you first opened either of them (the game, if that was a command or the config).

The Fuel Day Tracker can also show the **estimated profit** of the Inferno minions instead of the tracked one, for when you aren't AFKing and want a rough return from the minion inventories. It is a per-data-set setting, the **Profit: Actual/Estimated** button next to Data Sets (it applies to the set being shown, whether or not it is in use). In estimated mode each started day shows its **Est. profit** (the estimated return minus its fuel cost, and minus the Capsaicin Eyedrops if they are on) in green (10m or more), yellow (under 10m) or red (a loss), and its row is tinted the same way, the second blue line shows the estimated return, eyedrop cost and fuel grade, the Total Profit box becomes **Est. Total Profit**, hovering the blue line shows how it was worked out, and the Data Sets menu and `/it fuel` use the estimated profit for that set too. The estimate counts one spawn and one kill per Crude Gabagool (so a minion makes one every two actions), at the speed worked out from these, each of which can be switched on in the Profit Calculators > Inferno Profits options (their descriptions give the same numbers, to check them against the game):

| Speed source | Bonus |
|---|---|
| Rising Celsius | +18% per Inferno minion on the island, up to 10 minions (+180%). Taken from each day's own minion count, no toggle |
| Flycatcher | +20% (needs Spider Slayer 6) |
| Second Flycatcher | +20% |
| Beacon V + Power Crystal | +10% |
| Beacon V + Scorched Power Crystal | +11% (the +10% plus 1% for the Scorched Power Crystal) |
| Postcard | +5% |
| Mithril Infusion | +10% |
| Free Will | +10% (assuming the minion stays loyal) |
| Super Compactor 3000 | no speed change; compacts 192 Crude Gabagool into 1 Very Crude Gabagool |

The bonuses are all added together into one percentage (so +20% and +10% make +30%, not +32%), and only the fuel's own bonus (Fuel +1000%, Heavy +1500%, Hypergolic +2000%) multiplies on top of that sum. The fuel's grade is taken from the fueling messages, which show the colour of the fuel that was placed (blue Rare, purple Epic, gold Legendary); a day that had more than one grade uses the most used one, and the **Fuel Grade (if unknown)** option is only used for a day where no grade was seen. The minion tier sets the base time between actions (I 1013s down to XI 697s), and the result is rounded down to whole ticks. Rare and Epic fuel only count Crude Gabagool. Hypergolic fuel also counts its rare drops, per harvest: Chili Pepper 1 in 136, Inferno Vertex 1 in 5,950, Reaper Pepper 1 in 458,182, Inferno Apex 1 in 1,309,091 (doubled for tier X and XI minions) and Gabagool the Fish 1 in 3,927,273, plus 1 Hypergolic Ionized Ceramics per minion per fuel day. The **Capsaicin Eyedrops** toggle multiplies the chance of each per-harvest rare drop by 1.3 (not the ceramics), assumes they are used on every minion every day, and subtracts their crafting cost from the estimated profit. One craft (4 Chili Pepper, 128 Exportable Carrots, 128 Enchanted Carrot and 1 Water Hydra Head) makes 3 eyedrops, and each day crafts enough for its minions, rounded up: 31 minions need 11 crafts, which makes 33. Like the rare drops, the eyedrops do nothing, and cost nothing, with the other fuels. Gabagool the Fish and the Water Hydra Head aren't on the Bazaar, so they are worth the prices you type in **Gabagool the Fish Price** (default 5m) and **Water Hydra Head Price** (default 1.5m); `5000000`, `5,000,000`, `5m`, `750k` and `2b` all work, and a blank or invalid entry uses the default. The other ingredients are valued at the Bazaar sell offer, like everything else. With the Super Compactor on, the Crude Gabagool is valued as Very Crude Gabagool with decimals (a partial one counts as its share), falling back to the Crude price if the Very Crude one is missing. Everything is valued at the Bazaar sell offer taken at the moment each fuel day ended, and that price is saved on the day, so each day keeps its own prices and its profit doesn't change as the Bazaar moves (a fuel day's fuel cost is still the one from when it was fueled). A day that ended while the game was closed gets the price of the next time it is open (it is retried until the Bazaar answers, even across restarts). A day that ended before the prices were recorded, or that is missing some of them, is given the current ones once when the data set is loaded and keeps those from then on (the tooltip says so). A day still running uses the live price until it ends. The estimate is for minions you aren't AFKing next to, so it is item drops only, with no mob-kill coins, over the whole fuel day. A day that a time warp cut to 23 hours (which is now recorded on the day, shown as "Time warped" on its row) still gets its full 24 hours of production, and the days stay whole 24-hour days when the clocks change for daylight saving: days are counted by calendar date, so the 25-hour local day doesn't merge two days into one and the 23-hour one doesn't skip a date, and a whole-day time you typed in by hand that is an hour off only because of the clock change counts as whole days. Nothing stops you turning on two Flycatchers plus a compactor, even though a minion only has two upgrade slots, so that can't happen in game.

`/it infernoProfits` runs the same estimate for a whole fuel day on each of the three fuels at once, for the minions of the current cohort (the current day's minion count, including a manual one; give a number, e.g. `/it infernoProfits 31`, to use another count). It uses the minion tier, speed bonuses, Super Compactor, **Capsaicin Eyedrops** and prices from the Profit Calculators > Inferno Profits options, whatever the **Fuel Grade (if unknown)** is set to, and the loot is valued the same way (Bazaar sell offer; Rare and Epic only count Crude Gabagool, Legendary also counts its rare drops and the Hypergolic Ionized Ceramics, with the partial amounts that come out as an expected number of drops, so 0.1 Inferno Apex is a tenth of its price). The fuel is priced the way `/it fuelcost` does with **Gabagool Distillate Only**, at the Bazaar buy order and per minion: 2 Inferno Fuel Block and 6 Crude Gabagool Distillate, plus the Sulphuric Coal and Very Crude Gabagool the Gabagool is made of, which come to 1 Sulphuric Coal and 1/8 Very Crude for Rare, 25 and 3 for Epic (what the Fuel Day Tracker uses) and 301 and 36 for Legendary (12 Heavy Gabagool and 1 Sulphuric Coal). The Sulphuric Coal is priced from what it is crafted from, 4 Enchanted Coal and 1/4 Enchanted Sulphur each (so 4 and 0.25 for Rare, 100 and 6.25 for Epic, 1,204 and 75.25 for Legendary), and so is the cost in the Fuel Day Tracker and `/it fuelcost`. The eyedrops are only counted for Legendary fuel, and cost what they do in the Fuel Day Tracker.

Inside `fuel_days.json`, each minion's fuel state is one record in a `minions` list (its key, name, position, fuel expiry and queued units), and each day lists the short refs (`m1`, `m2`, ...) of the minions counted toward it rather than repeating their full keys. Earlier versions stored this as three separate maps keyed by the full minion key, which repeated each key — up to ~210 characters for a coordinate-based one — hundreds of times at the top of the file. Both layouts load, so existing saves, test files and older backups are read unchanged and are rewritten in the new layout on the next save.
